Student: Salma Mohamed Hashem (Member 1 - Accounts, Authentication & Administration)
Tool: Claude
prompt: 
How to implement Http cookies req
How output was used:
ACC-06 (logout/session handling): login should set the auth cookie, and logout should clear it. The requirement also mentions revoking the refresh token and ending an idle session after 30 minutes, so setting a cookie alone won’t finish all of ACC-06.
Your current login returns the access token in the JSON response. Moving it into an HttpOnly cookie is part of implementing that cookie-based auth flow.
@Res({ passthrough: true }) lets Nest set the cookie while still returning your normal JSON response. The cookie uses HttpOnly, and secure turns on automatically in production over HTTPS. 
Your AuthService.login() should keep returning { accessToken, user }; the controller puts the token in the cookie and returns only the user to the client.

Test it in Swagger:
1. Restart the backend and open http://localhost:3000/docs.
2. Run POST /auth/login.
3. In the response, check that you see the user but no accessToken.
4. In browser DevTools, check Network → login request → Response Headers for Set-Cookie.
5. Run POST /auth/logout, then check that the cookie is cleared.
This logout endpoint clears the browser’s cookie. Your 1h JWT can still be used until it expires if someone already copied it; server-side token revocation needs a refresh-token/session record. Also, a cookie with a 30-minute lifetime would expire 30 minutes after login, not after 30 minutes of inactivity; idle-timeout enforcement is a separate step.
